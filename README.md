# A股舆情驱动量化交易系统

从财经快讯、社交热搜、行情和国际市场等多个来源采集数据，由大语言模型（LLM）分析舆情，再用多因子加权模型给涨停股打分，预测下一交易时段最可能涨停的股票，并生成交易信号和模拟盘订单。系统会根据历史信号的实际结果自动调整因子权重。

> **免责声明：** 本项目仅供学习和研究使用，输出结果不构成任何投资建议。股市有风险，据此操作风险自负。

## 功能

- **多源数据采集：** 并发采集行情、涨停池、龙虎榜、北向资金、财经快讯、社交热搜、美股和国际新闻，单个数据源失败时自动切换备用源；连续失败的数据源自动熔断，桌面端可查看各数据源状态。
- **大盘环境：** 从涨跌家数、指数、赚钱效应、晋级率、涨跌停、连板高度、封板质量、量能评估市场处于进攻、均衡、防守还是冰点，并据此控制新开仓仓位。
- **主线分析：** 用近 5 日涨停池，按概念题材（同花顺涨停原因）和所属行业两个维度计算热度，判断所处阶段（启动、加速、持续发酵、降温、退潮），识别龙头和梯队。
- **LLM 大盘复盘：** 按趋势结构、资金情绪、主线板块复盘当天市场，给出次日姿态、仓位、关注与回避方向和观察要点；AI 给出的姿态不会比量化大盘环境更激进。
- **全市场策略选股：** 用放量突破、强势未板、龙回头、主线补涨、缩量回踩、超跌反弹 6 个策略扫描全市场，按大盘环境标注是否适配，作为 AI 涨停预测的候选来源；可以用历史数据回测各策略，并按回测表现调整策略排序权重。
- **LLM 舆情分析：** 对新闻做情感分析和题材提取，评估国际事件对 A 股板块的影响；财联社重要快讯到达后会立即送入 LLM 分析。
- **综合评分：** 8 个因子加权打分，输出 Top N 选股和买入信号。
- **AI 涨停预测：** 按盘前、早盘、午间、午后、盘后不同时段使用不同的提示词，结合大盘环境和主线梯队，预测最可能涨停的 10 只股票，并给出买入价、止损价和目标价。AI 返回的股票会校验：数据库中不存在的代码（编造的）、ST 和退市股会被剔除。
- **个股查询：** 按代码、名称或拼音首字母搜索任意 A 股，查看 K 线、新闻公告和 AI 诊断；本地日线不足时自动联网补齐。
- **个股 AI 诊断：** 汇总单只股票的行情、估值、技术面、资金流、筹码、业绩、个股新闻和公告、涨停记录、主线地位、大盘环境，由技术面、情报（、风险）分析员分别分析后，决策员给出评分、操作建议、价格计划、利好、风险和检查清单，并标注数据完整度和分析员分歧；之后按实际走势验证诊断的准确率，并用历史准确率校准信心。诊断历史独立页面可按股票、操作建议、天数筛选，支持下载 Markdown 或分享图。
- **图片识别导入：** 自选股页可识别截图中的股票列表（支持 PNG/JPEG/WebP/GIF），或直接粘贴剪贴板图片；识别出的股票经校验后勾选加入自选。LLM 支持图片输入时即可启用。
- **自选股决策仪表盘：** 管理自选股（搜索添加、粘贴或导入 CSV/Excel），收盘后逐只 AI 诊断，推送买入/观望/卖出汇总、每只结论和与上次诊断的变化。
- **AI 问股：** 多轮对话，回答逐字实时显示、可随时停止；AI 按需查询行情、技术面、资金流、新闻公告、主线、大盘等数据后回答，可选择打板接力、龙回头、主线补涨等分析视角。
- **AI 研判：** 定时任务生成评分信号后，由 AI 对 Top 股票给出买入、观望或回避；观望和回避的信号不下单。
- **技术面分析：** 均线趋势、量价、MACD、RSI、乖离率，输出理由和风险提示；按打板策略调整，乖离率只作为高位风险扣分。
- **自学习：** 每天用信号之后的行情检验历史信号，按各因子的实际表现调整权重，并评估各新闻源的可信度。
- **信号绩效回测：** 统计信号 1/3/5 日胜率、平均收益、涨停命中率，模拟止损止盈离场，按信号类型、来源和 AI 研判分组。
- **风控与模拟交易：** 仓位上限、止损止盈、大盘熔断、ST 与股票池过滤；信号自动转为模拟盘待确认订单，持仓触及止损价或目标价时自动生成卖单，模拟 A 股 T+1。
- **盘中提醒：** 交易时段内监控今日信号股、模拟盘持仓和自选股，封涨停、炸板、跌破或接近止损、达到目标价、大跌、大盘环境转弱，以及自定义的价格、涨跌幅、放量、均线、MACD、KDJ、RSI 规则触发时推送；同一提醒有冷却期，可设置免打扰时段；支持系统错误通知、盘中提醒日报和分享图推送（企业微信、Telegram、邮件、Discord、ntfy）。
- **实盘记账：** 手动记录或导入券商交割单，计算真实持仓、成本、浮动和已实现盈亏；支持录入或导入分红、送股、送转等公司行为（影响成本摊薄和持仓数量）；实盘持仓同样享有止损提醒、组合风险、个股诊断和问股（只记账，不连券商、不下单）。
- **组合风险：** 模拟盘和实盘的总仓位与大盘环境是否匹配、个股和行业集中度、止损距离、最大回撤和当前回撤。
- **决策信号：** 个股诊断给出买入、加仓、减仓、卖出、回避时生成决策信号，带 AI 给出的观察期（1~20 个交易日）和失效条件，出现相反信号时旧信号自动失效；收盘后自动评估历史信号的收益和止损止盈情况；Web 决策信号页可查看和反馈；单票历史信号表现写进诊断提示词，辅助 AI 决策。
- **深度研究：** 按选定的议题自动拆解问题、联网搜索、收集本地行情与新闻、技术面和主线等证据，由 LLM 汇总生成带证据引用的研究报告；可下载 Markdown；机器人支持「研究」命令。
- **ETF 与指数：** 支持 12+ 个内置指数和全市场 ETF（新浪列表），单独入库（`fund_daily`/`fund_info`），不混入涨跌家数和大盘环境计算；支持搜索、K 线查看、AI 诊断、问股工具和机器人诊断；不能加入自选股和交易。
- **多策略会诊：** AI 诊断时按大盘环境和个股特征自动挑选 1~2 个策略（如打板接力、龙回头、放量突破），各自给出观点后汇总给决策员（每次诊断多约 2 次模型调用，可在配置里关闭）；策略表现通过实际命中率自动调整权重，可在决策信号页查看。
- **诊断运行记录：** 每次 AI 诊断会记录各处理步骤的耗时、模型调用、护栏调整；诊断历史可查看；且绘制该股票的评分与收盘价趋势图。
- **每日推送：** 收盘后把大盘复盘（含 AI 复盘与次日计划）、交易信号、待确认订单、模拟盘账户和信号绩效推送到已启用的渠道；每类消息可以指定推送渠道，界面上可检查配置、发送测试消息。支持企业微信、钉钉、飞书、邮件、Telegram、Discord、Slack、PushPlus、Server酱、ntfy、Gotify、Pushover、Bark、自定义 Webhook；支持把日报和仪表盘分享图推送给部分渠道，推送失败自动回退文字。
- **聊天机器人：** 在钉钉、飞书、Discord 里诊断、批量、历史、策略查询或直接提问（AI 问股），通过长连接收消息，不需要公网 IP（Discord 支持 Gateway 连接）。
- **首次配置向导：** 首页提示未完成的关键项（大模型、数据、交易日历、推送、自选股、浏览器等），点击跳转到设置向导；设置页每个标签有中英文帮助按钮，支持 `?tab=` URL 直达具体标签。
- **桌面端自动更新：** Electron 桌面端启动时检查 GitHub Release 上的新版本（可在设置禁用），发现新版本时下载并在 Windows 上重启安装、macOS 上提示下载；菜单可手动检查更新。
- **AI 用量统计：** 大模型通过 LiteLLM 接入，每个模型可填多个 API Key（被拒绝或限流时自动换下一个，该 Key 冷却 10 分钟），支持 Claude、Gemini、Ollama 本地模型和所有兼容 OpenAI 接口的平台；每次调用的 token 和估算费用按天、功能、模型汇总；设置页「获取模型列表」按需联网获取指定 API 的可用模型。
- **定时任务与配置备份：** Web【设置】可查看各定时任务的触发规则和下次运行时间并立即运行；配置可导出备份（默认隐藏密钥）和导入恢复。
- **多种运行方式：** Web 界面（React + FastAPI，可在手机上用）、Electron 桌面端（Windows 安装包、macOS dmg，支持自动更新）、Docker、GitHub Actions 定时运行、无界面定时任务；原 PyQt6 桌面端仍可使用。
- **国际化：** 界面支持中文/英文切换（顶栏和登录页的语言按钮，浏览器会记住选择），设置和帮助按界面语言切换；AI 回答、报告、新闻不翻译。

## 数据源

| 类别 | 来源 |
|---|---|
| 实时行情 | 腾讯财经 → 东方财富 → AKShare（新浪）→ efinance → 通达信（pytdx），依次回退 |
| 涨停池、龙虎榜、北向资金 | 东方财富 |
| 涨停原因（概念题材） | 同花顺涨停池 |
| 个股资金流 | 同花顺 → 东方财富 |
| 筹码分布 | AKShare → 本地日线估算 |
| 业绩预告、业绩快报 | 东方财富（AKShare） |
| 个股新闻、公告 | 东方财富 |
| 个股历史日线（回补、按需补齐） | 腾讯 → 新浪 → 东方财富 → baostock → 通达信 → efinance → Tushare Pro（需要 token） |
| ETF 与指数日线 | 腾讯 K 线（存入独立的 fund_daily 表，不混入涨跌家数和大盘环境计算） |
| 财经资讯 | 财联社电报、雪球、韭研公社、同花顺热股、东方财富热门概念、RSS 订阅源 |
| 社交热搜 | 微博、抖音、今日头条 |
| 国际新闻 | 财联社国际、华尔街见闻、金十数据、东方财富全球 |
| 美股 | 重点公司财报（Mag7、半导体、中概股龙头）、VIX、美元兑人民币汇率 |

东方财富、同花顺等网站有反爬检测，这些数据通过 Playwright 驱动的无头 Chromium 获取。实时行情和日线的回退顺序可以在 `data_sources` 配置里调整。

`python scripts/check_sources.py` 会逐个请求各数据源，列出是否可用、条数和用时（不写数据库），用来确认接口有没有变化。

数据源稳定性：

- **熔断：** 实时行情、涨停池按优先级依次尝试各数据源。某个源连续失败 3 次后，跳过它 5 分钟，之后放行一次探测请求，成功则恢复。
- **健康状态：** 指数、板块、北向资金、各资讯源和美股数据都会记录成功和失败情况，桌面端【数据源状态】页和日报会显示异常的数据源。Web【数据源状态】页的「能力总览」按数据集列出回退顺序、是否已配置和健康状态。
- **避免错位数据：** 行情和涨停池按当天日期入库，所以非交易日和交易日 9:25 之前不采集，这时接口返回的是上一个交易日的数据。
- **科创板成交量修复：** 腾讯实时行情字段 36 中，科创板（688/689）已是股，其余板块是手（需要乘以 100）；日线按「成交额/(收盘价×成交量)」判断单位并自动转换；`python scripts/repair_star_volume.py` 可修复已入库的错误数据（默认预览，`--apply` 才写入）。

## 环境要求

- Python 3.10 及以上（CI 使用 3.12，也在 3.14 上测试）
- Node.js 22 及以上（构建 Web 前端和桌面端；CI 使用 24）
- Chromium（通过 Playwright 安装；Docker 镜像和打包的桌面端会自动准备）
- 至少一个大模型 API Key：DeepSeek、通义千问、智谱 GLM、Kimi、百度文心、豆包、硅基流动、OpenAI、Claude、Gemini，或本地的 Ollama（不需要 Key）
- Windows、macOS、Linux 均可运行

## 快速开始

```bash
git clone git@github.com:hongheshan-svg/quant_tools.git
cd quant_tools

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium

cp config/settings.yaml.example config/settings.yaml
```

编辑 `config/settings.yaml`，至少填入 `llm.primary.api_key`（也可以启动后在界面的【设置】里填写）。然后构建前端并启动 Web 服务：

```bash
cd apps/web && npm ci && npm run build && cd ../..
python server.py
```

浏览器打开 http://127.0.0.1:8000 。`server.py` 同时运行定时任务和聊天机器人，相当于 `main.py` 加上 Web 界面。

想用桌面窗口，可以运行 Electron 桌面端（开发模式直接使用仓库里的配置和数据）：

```bash
cd apps/desktop && npm install && npm run dev
```

原来的 PyQt6 桌面端仍然可用：`python run_dashboard.py`。

数据库（`data/quant.db`）和日志目录（`logs/`）首次运行时自动创建。

## 运行方式

| 命令 | 说明 |
|---|---|
| `python server.py` | Web 界面和 API（默认 http://127.0.0.1:8000），同时运行定时任务和聊天机器人；`--no-scheduler` 只提供界面和接口（已经在运行 `main.py` 时用），`--host 0.0.0.0` 让局域网访问（需要先开启 Web 登录），`--workdir` 指定存放 `config/`、`data/`、`logs/` 的目录 |
| `cd apps/desktop && npm run dev` | Electron 桌面端（开发模式），自动在空闲端口启动 `server.py` 并打开 Web 界面 |
| `python run_dashboard.py` | PyQt6 桌面端（旧版）：股票搜索、交易决策、实时资讯流、AI 问股、自选股、模拟交易（含组合风险）、实盘记账、信号绩效（含 AI 诊断验证）、大盘复盘、策略选股（含历史回测）、主线分析、盘中提醒、数据源状态；个股详情含 K 线、新闻公告、AI 诊断和加入自选；AI 涨停预测、推送日报、推送设置 |
| `python run_dashboard.py --headless` | 不打开界面，执行一次完整流程（采集 → 自学习 → 涨停预测 → 生成订单）后退出 |
| `python run_dashboard.py --warmup-before-ui` | 先执行一次完整流程，再打开界面 |
| `python main.py` | 无界面常驻运行，按下方时间表定时执行，并运行聊天机器人 |
| `python main.py --once` | 按顺序执行一遍收盘后的任务（采集 → 每日分析 → 交易信号 → 大盘复盘与日报 → 自学习 → 自选股仪表盘）后退出，`--steps collect,analysis` 只执行部分步骤；供 GitHub Actions、Docker 或系统定时任务使用 |
| `python main.py --stocks 600519,000858` | 只诊断指定股票并推送决策仪表盘（跳过采集、分析等步骤） |
| `python main.py --no-notify` | 运行任务但不推送消息 |
| `python main.py --check-notify` | 检查推送配置后退出（退出码 0 为可用，1 为失败） |
| `python run_full.py` | 基于已采集数据一次性执行：舆情分析 → 题材提取 → 国际因子 → 评分，打印 Top 10 |
| `python run_score.py` | 只对已有数据评分 |
| `python run_demo.py` | 演示数据采集与展示 |
| `docker compose -f docker/docker-compose.yml up -d` | Docker 运行 Web 界面和定时任务，见下方 [Docker](#docker) |
| `python scripts/check_sources.py` | 检查各数据源是否可用 |
| `python scripts/fetch_history.py --mode daily --start-date 2024-01-01` | 回补历史数据；`--mode` 可选 `all`、`daily`、`limit_up`、`concepts`（给已有涨停记录补齐题材）、`dragon_tiger`；默认断点续传并补齐 `--start-date` 之后缺失的日线，`--force-full` 全量重拉，`--overwrite` 覆盖已有日线 |

`main.py` 和 `server.py` 的默认时间表（可在 `scheduler` 配置中修改）。行情采集和每日任务按交易日历运行，周末和法定节假日自动跳过；新闻类采集照常进行。

| 自学习 | 工作日 16:20 |

## Web 界面与桌面端

## 大盘环境与主线

**大盘环境**（`src/analyzers/market_regime.py`）参考「趋势结构 → 资金情绪 → 行动框架」的三段式复盘，满分 100：

| 维度 | 分值 | 指标 |
|---|---|---|
| 趋势 | 35 | 涨跌家数比、三大指数平均涨跌幅 |
| 短线情绪 | 45 | 昨日涨停股今日平均涨幅（赚钱效应）、涨停/跌停家数、最高连板、一次封板率 |
| 量能 | 20 | 成交额较前一交易日变化 |

按总分分为四档，并对应新开仓的仓位系数：

| 档位 | 总分 | 仓位系数 |
|---|---|---|
| 进攻 | 65 分以上 | 1.0 |
| 均衡 | 40–65 分 | 0.6 |
| 防守 | 20–40 分 | 0.3 |
| 冰点 | 20 分以下 | 0，暂停新开仓 |

仓位系数可在 `risk.market_regime_position` 中配置。另外给出短线情绪周期：高潮、升温、震荡、退潮、冰点。当天有行情的股票少于 300 只时视为数据不足，不做仓位调整。

**主线**（`src/analyzers/theme_tracker.py`）按两个维度计算每日热度：

- **维度：**
  - **题材：** 同花顺涨停原因里的题材标签，如「海峡两岸+工程机械」。一只股票可以属于多个题材，所以能识别分散在不同行业的题材主线。「业绩增长」这类基本面原因，以及只属于一只股票的标签（个股事件），不算题材。
  - **行业：** 东方财富涨停池的「所属行业」。
- **热度：** `10 × 涨停家数 + 8 × (最高连板 - 1) + 5 × 连板家数`，满分 100，40 以上视为热门。题材主线还要求当天至少 2 家涨停。
- **阶段：** 看最近 5 个交易日的热度趋势、持续性和回落幅度，判断为启动、加速、持续发酵、降温或退潮。
- **龙头与梯队：** 龙头是板块内连板最高、同高度时封板最早的股票，其余为跟风。

AI 涨停预测、个股诊断、日报和桌面端都会使用大盘环境和主线结果。

**LLM 大盘复盘**（`src/services/market_review.py`）把指数、涨跌家数、成交额、大盘环境、题材和行业主线、降温板块、财联社重要快讯交给 AI，按「趋势结构 → 资金情绪 → 主线板块」复盘，输出次日姿态（进攻、均衡、防守）、建议仓位、关注方向、回避方向和观察要点。AI 给出的姿态不能比量化大盘环境更激进，例如大盘环境为防守时，AI 说进攻也会下调为防守，仓位按 0~3 成处理。每个交易日保存一份，写进日报，桌面端【大盘复盘】页可查看或重新生成。

## 策略选股

全市场策略选股（`src/strategy/screener.py`）每天收盘分析后运行，桌面端【策略选股】页也可手动运行：

1. 取最新交易日的全市场行情，按 `config/stock_pool.yaml` 过滤 ST、黑名单、股价和流通市值。
2. 对成交额 3000 万以上的股票取近 60 个交易日的日线，计算均线、量比（用成交额计算）、20 日平台、回撤、近期涨停次数等特征。
3. 逐个策略判断并打分（0~100）：

| 策略 | 条件 | 适配环境 |
|---|---|---|
| 放量突破 | 放量 2 倍以上突破 20 日平台高点，站上 MA20，收盘在全天高位，尚未涨停 | 进攻、均衡 |
| 强势未板 | 涨 6% 以上未涨停，收在全天最高价附近，放量，换手 3%~25% | 进攻、均衡 |
| 龙回头 | 近 15 个交易日至少 2 次涨停，从高点回撤 8%~25%，缩量，收盘不低于 MA20 的 97% | 进攻、均衡 |
| 主线补涨 | 属于当前主线（近 60 天因该题材或行业涨停过），今天涨 3% 以上但未涨停 | 进攻、均衡 |
| 缩量回踩 | 均线多头排列，20 日涨 5%~40%，缩量回踩 MA10 | 均衡、防守 |
| 超跌反弹 | 20 日跌 20% 以上后放量反弹 3% 以上，收盘偏强 | 防守、冰点 |

4. 与当前大盘环境适配的策略排在前面；同一只股票被多个策略选中会加分。结果保存到数据库，AI 涨停预测在盘前和盘后把它作为「全市场」来源的候选。【策略选股】页同时统计近 30 天各策略选股的次日平均涨幅、上涨比例和涨停比例。

策略参数可以在 `screening.strategies` 中覆盖，也可以关闭某个策略，例如：

```yaml
screening:
  strategies:
    volume_breakout: {vol_ratio_min: 2.5}
    oversold_rebound: {enabled: false}
```

策略选股依赖日线历史。日常采集只保存每天的行情，第一次使用前先回补最近 60 个交易日：

```bash
python scripts/fetch_history.py --mode daily --start-date 2026-06-01
```

用旧版本回补过日线的，加 `--overwrite` 重新下载一次：旧版本把腾讯日线的成交量、成交额写错了单位，会影响量比。

**历史回测与策略权重：** 【策略选股】页点【历史回测】，用本地日线回测近 60 天：

- **选股：** 每个交易日都只用当天及以前能看到的数据重新选股，包括日线、涨停题材、主线和大盘环境。
- **入场：** 次日开盘价。
- **统计：** 各策略 1/3/5 日收益、胜率、次日涨停率，以及适配大盘环境时的收益；每天等权买入当天全部入选股票，得到累计收益和最大回撤。
- **自动回测：** 每日分析时，距上次回测超过 7 天会自动回测一次，天数由 `screening.backtest_interval_days` 设置。
- **跳过的日期：** 当天行情不足 1000 只的日期不回测，所以要先回补全市场日线。

回测样本足够的策略会按次日平均收益温和调整排序权重（0.8~1.2），关闭用 `screening.adaptive_strategy_weights: false`。

## 盘中提醒

交易时段内每次采集行情后检查今日信号股、模拟盘和实盘持仓、自选股，以及 `alerts.watchlist` 中的股票：

- **内置提醒：** 封涨停、炸板、跌破止损价（紧急）、达到目标价、跌幅超过 `alerts.big_drop_pct`。
- **持仓与大盘：** 持仓现价距止损价不到 `alerts.near_stop_pct`（默认 2%）时提醒「接近止损」。大盘环境比前一交易日降档（如均衡转防守，转为冰点时是紧急提醒），或评分下降 `alerts.regime_score_drop`（默认 15 分）以上时提醒。
- **自定义规则：** Web 页面【盘中提醒】标签页可直观编辑规则，支持价格突破、涨跌幅、成交量放大倍数，以及技术指标：
  - 价格上穿或下穿 N 日均线；
  - MACD、KDJ 金叉或死叉；
  - RSI 上穿或下穿阈值。
  规则支持启用开关和备注；保存前逐条校验。指标用日线计算，当天的数据就是最新价。本地日线不足时会先自动补齐。每条指标规则每天只提醒一次。
- **立即试算：** 可在 Web 页面对规则进行测试，不受交易时段和冷却限制，试算结果不写记录不推送。
- **推送渠道：** 可以在【推送设置】里让盘中提醒只发到某个渠道（如只发飞书），日报、自选股仪表盘发到邮件。
- **降噪：** 同一提醒在 `alerts.cooldown_minutes` 内不重复推送，封涨停每只股票每天只提醒一次；`notifier.quiet_hours` 设置的免打扰时段内只推送紧急提醒；同一次检查的多条提醒合并成一条消息。
- **记录：** 所有提醒都会记录，包括没有推送的，桌面端【盘中提醒】页可查看。

## 评分模型

综合评分由 8 个因子加权得出，默认权重如下（在 `strategy.weights` 中配置）：

| 因子 | 配置键 | 权重 |
|---|---|---|
| 舆情 | `sentiment_score` | 25% |
| 连板高度 | `limit_up_score` | 15% |
| 封单强度 | `seal_strength` | 15% |
| 板块效应 | `sector_effect` | 12% |
| 资金流向 | `capital_flow` | 10% |
| 国际因子（美股财报、国际事件） | `global_score` | 10% |
| 技术面 | `technical` | 8% |
| 市场情绪 | `market_emotion` | 5% |

开启自学习（`strategy.learning.enabled`）后，系统每天把学到的权重写入 `strategy.adaptive_weights`，实际权重为 `基础权重 × 65% + 自学习权重 × 35%`，比例由 `strategy.learning.blend_ratio` 控制。

## 模拟交易

信号生成后会自动转为订单，默认需要人工确认：

1. 定时任务每个工作日 16:00 生成交易信号，或在桌面端点击【AI涨停预测】。
2. 定时任务先由 AI 研判 Top 评分股，再把买入信号转为「待确认」订单。委托价优先用 AI 给出的买入价，没有时用最新收盘价。评分引擎中评级为「观望」、或 AI 研判为观望或回避的股票只作关注，不下单。每笔买单都要经过风控和股票池校验，未通过的记为「已拒绝」并写明原因。
3. 在桌面端【模拟交易】页选中订单，点【确认下单】提交到模拟盘，或点【撤销订单】。该页同时显示账户资金、持仓、止损价、目标价和浮动盈亏。
4. 每次采集行情后检查持仓：最新价跌破止损价或达到目标价时生成「待确认」卖单（每只股票每天最多一笔）。止损价和目标价优先用买入信号的价格计划，没有时按 `risk.stop_loss_pct` / `risk.take_profit_pct` 计算。

几点说明：

- 模拟盘按委托价立即全部成交，不模拟滑点；按 A 股 T+1 规则，当天买入的股票次日才能卖出。
- AI 给出的价格会按最新价和各板块涨跌幅限制校验，超出范围的价格会被丢弃。
- 黑名单和股票池只限制买入，止损止盈卖出不受限制。
- 同一只股票同一天同类信号只生成一次订单，重复执行不会重复下单。
- 账户状态由数据库中的成交记录重放得到，程序重启后资金和持仓保持连续。
- 设置 `trading.auto_confirm: true` 后，订单生成即自动确认，只对模拟盘生效；设置 `trading.execution_enabled: false` 可关闭自动生成订单，但仍可在【模拟交易】页手动点【生成订单】。

## 信号绩效

桌面端【信号绩效】页统计近 60 天的交易信号：

- **入场：** 开盘前生成的信号按验证日开盘价入场，盘中生成的按当天收盘价入场。验证日指 AI 预测的目标交易日；评分信号是在收盘后生成的，验证日取下一个交易日。
- **收益与胜率：** 统计入场后第 1、3、5 个交易日收盘时的收益和胜率，以及验证日的涨停命中率。
- **止损止盈模拟：** 从入场次日开始按日线判断止损止盈；开盘就跳空越过止损价或止盈价时，按开盘价离场；同一天同时触及止损和止盈时，按止损处理。
- **分组：** 按信号类型、来源（热点驱动、涨停板、全市场、综合评分）和 AI 研判分组，可以看出哪类信号更可靠。

同一页的【AI 诊断验证】子页检验近 60 天的个股 AI 诊断：

- **基准价：** 诊断依据的行情日收盘价，统计之后 1/3/5 日的涨跌。
- **方向准确率：** 买入、加仓算看多，减仓、卖出、回避算看空；看多后上涨、看空后下跌算判断正确。
- **价格计划：** 看之后 5 个交易日先碰到止盈价还是止损价。
- **分组：** 按操作建议和评分区间分组，可以看出高分诊断是否真的更准。

## 个股 AI 诊断

用顶部搜索框（代码、名称或拼音首字母，如 `zyhk`）或在表格中双击股票，打开个股详情。本地日线不足 60 根时会自动联网补齐；【新闻公告】页显示近 7 天个股新闻和近 30 天公告，含立案、减持、问询等关键词的公告会标注风险。

详情窗口的【AI诊断】页中，AI 会结合以下材料输出一份决策仪表盘：

- **汇总的材料：** 最新行情和估值（市盈率、市净率）、技术面、个股资金流、筹码分布（获利比例、平均成本、集中度）、业绩预告和快报、近 10 日涨停记录（连板、封板时间、炸板、封单）、主线地位、大盘环境、相关快讯与个股新闻、近 30 天公告、AI 舆情、龙虎榜、模拟盘和实盘持仓。
- **输出内容：** 评分、操作建议（买入、加仓、持有、观望、减仓、卖出、回避）、一句话结论、空仓与持仓建议、价格计划、利好、风险和检查清单。

**多智能体诊断**（`diagnosis.mode`）：

- **single：** 一次调用。
- **standard（默认）：** 技术面分析员只看走势、指标、筹码、资金流和涨停质量，情报分析员只看新闻、公告、舆情、业绩和龙虎榜，两人同时分析；决策员拿到全部数据和两人的观点后给出最终结论。共 3 次调用。
- **full：** 再加一位风险分析员，共 4 次调用。
- **分歧：** 分析员一个看多、一个看空，或评分相差 25 分以上时，页面会标出分歧，信心最高给「中」。

**历史校准**（`diagnosis.calibration`）：近 90 天诊断的事后准确率和本股最近几次诊断的结果会写进提示词。看多诊断的 3 日方向准确率低于 45%（至少 10 次）时，买入建议的信心下调一档。

结果还会经过几道校验：

- 评分低于 50 却建议买入时，降级为观望。
- 大盘处于冰点时不给买入建议。
- 数据完整度不足 60%，或行情、日线数据不足时，不给买入建议。数据完整度按行情、日线、技术面、资金流、筹码、大盘、资讯、业绩的有无加权计算。
- 资金净流出超过成交额的 5% 时，不给买入建议。
- 与 3 天内的上次诊断方向相反、但评分变化不足 15 分时，看多的改判暂按观望处理，看空的改判保留。
- 近 30 天公告含立案调查、退市风险警示等严重风险时，不给买入建议。
- 不合理的价格会被丢弃。

诊断结果保存在数据库中，30 分钟内再次打开会直接复用。

## 自选股

【自选股】页可以用代码、名称或拼音首字母添加股票（个股详情里也能「加入自选」），或批量导入：

- **粘贴导入：** 粘贴一段文字，比如券商 App 的自选股列表或聊天记录，自动识别其中的 6 位代码和股票名称。
- **文件导入：** CSV、Excel 或 TXT。表格有「代码」列表头时只读取代码列，持仓数量、金额这类 6 位数字不会被误认成代码。

每个交易日 16:30（`scheduler.watchlist_report_time`），或在页面点「分析全部并推送」，会逐只 AI 诊断并生成**决策仪表盘**：

- **汇总：** 买入/加仓、持有/观望、减仓/卖出/回避各几只。
- **每只股票：** 结论、评分、一句话理由、与上一次诊断相比的变化（如「观望→买入，评分 55→72」）、价格计划、利好、风险和护栏。
- **推送与复用：** 仪表盘推送到已启用的渠道。收盘后已经诊断过的股票直接复用，不重复调用 AI。

自选股最多 `watchlist.max_stocks`（默认 50）只，每只每天一次诊断。盘中提醒也会关注自选股。

## 实盘记账

【实盘记账】页只记账，不连券商、不下单：

- **成交流水：** 点「记一笔」手动记录，或「导入交割单」导入券商导出的交割单/成交记录（CSV 或 Excel）。系统按常见列名识别成交日期、证券代码、买卖标志、成交价格、成交数量和佣金、印花税、过户费等；红利、转账等非买卖行会跳过。重复导入同一份交割单不会重复记账。
- **持仓与盈亏：** 按移动平均成本计算，费用计入成本；卖出时结算已实现盈亏。
- **可用资金：** 点「设置可用资金」填入券商账户当前的可用资金，之后的成交会自动增减。没设置时总资产只按持仓市值计算，也不做总仓位检查。
- **止损止盈：** 可以逐只设置止损价和目标价；没设置时按 `risk.stop_loss_pct` / `take_profit_pct` 从成本计算。

实盘持仓会进入盘中提醒（跌破止损、接近止损、达到目标价）、组合风险、个股诊断和 AI 问股。

## AI 问股

【AI 问股】页可以多轮追问，例如「中远海控现在能买吗？止损放哪？」「今天的主线是什么？」「我的持仓风险大吗？」：

- **查询数据：** AI 每个问题最多查询 3 轮，数据来自本地数据库和已有的数据源，包括股票查找、行情和估值、日线、技术面、资金流、筹码、业绩、新闻公告、涨停记录、主线、大盘环境、策略选股、模拟盘和实盘持仓、自选股和历史诊断；还可联网搜索相关资讯。
- **只读：** AI 不能下单，也不能修改数据。
- **分析视角：** 可选 19 种分析策略，包括打板接力、龙回头、主线补涨、放量突破、缩量回踩、超跌反弹、事件驱动、波浪理论、缠中说禅等，AI 会按所选策略的判断标准回答。
- **导出与推送：** 回答会列出查询过哪些数据；整段对话可以导出为 Markdown，最近一次回答可以推送到机器人。
- **模型兼容：** 工具调用用 JSON 协议实现，不依赖模型的 function calling，所有兼容 OpenAI 接口的模型都能用。

## 组合风险

【模拟交易】页的「组合风险」区域和【实盘记账】页每次刷新时计算：

- **总仓位：** 与大盘环境建议的最高仓位比较（进攻 100%、均衡 60%、防守 30%、冰点 0，取自 `risk.market_regime_position`）。
- **集中度：** 单只持仓超过 `portfolio_risk.single_max_pct`（默认 30%）时提示；同一行业合计超过 `sector_max_pct`（默认 50%）时提示，行业取股票最近一次涨停时的所属行业。
- **止损距离：** 距止损价不足 `near_stop_pct`（默认 3%）或已经跌破时提示。
- **回撤：** 按成交记录和每日收盘价重放账户净值，给出最大回撤和当前回撤。

## 配置

主配置文件为 `config/settings.yaml`（已被 git 忽略，从 `settings.yaml.example` 复制）。本地文件只需写要修改的项，其余自动沿用 example 中的默认值。

| 配置段 | 内容 |
|---|---|
| `llm` | 主模型、备用模型（主模型失败时自动切换）、图片识别模型（`vision`，留空用主模型）、调用方式（`backend`：litellm / openai）、超时、重试、响应缓存、自定义单价（`pricing`，用于估算费用） |
| `scheduler` | `main.py` 的采集间隔和每日任务时间 |
| `trading` | 交易时段；交易执行开关、自动确认、单笔订单预算、每次最多订单数、模拟盘初始资金、是否按大盘环境调整仓位 |
| `strategy` | 因子权重、自学习参数、Top N 数量、AI 研判开关 |
| `screening` | 全市场策略选股开关、入选数量、各策略参数、策略权重开关、自动回测间隔 |
| `portfolio_risk` | 组合风险的单只和行业集中度上限、止损距离提示 |
| `market_review` | LLM 大盘复盘开关 |
| `alerts` | 盘中提醒开关、冷却时间、大跌阈值、接近止损阈值、大盘转弱提醒、自选股、自定义规则（含技术指标） |
| `risk` | 单只仓位上限、单日买入上限、止损止盈、大盘熔断、大盘环境对应的仓位系数、黑名单关键词 |
| `global_data` | 重点跟踪的美股公司及其对应的 A 股板块 |
| `desktop` | 桌面端刷新间隔、并发线程数、是否实时 AI 分析快讯 |
| `notifier` | 每日报告开关、免打扰时段；企业微信、钉钉、飞书机器人 Webhook（钉钉、飞书支持签名）；邮件（SMTP）；Telegram、Discord、Slack、PushPlus、Server酱、ntfy、Gotify、Pushover、Bark、自定义 Webhook；按消息类型的推送路由 `routes`。桌面端【推送设置】可以直接修改 |
| `diagnosis` | 个股诊断模式（single / standard / full）、历史校准开关 |
| `watchlist` | 自选股每日仪表盘开关、自选股上限、同时诊断的股票数 |
| `intelligence` | RSS 资讯源开关、更新间隔（最少 5 分钟）、每个源最多条数、保留天数、订阅源列表 |
| `web` | Web 服务地址和端口、登录开关、会话天数、API Token、是否同时运行定时任务、后台任务并发数、跨域来源 |
| `bot` | 钉钉、飞书聊天机器人的凭证和开关，允许使用的用户 |
| `data_sources` | 日线回补和实时行情的数据源顺序、Tushare token、自定义通达信服务器 |

股票池过滤规则在 `config/stock_pool.yaml`，下单前由风控模块逐条校验（策略选股也按其中的黑名单、股价和市值过滤）：

- **黑名单：** 指定代码，以及名称中含 ST、\*ST、退 等关键词的股票。
- **上市天数：** 默认上市不足 60 个自然日的次新股不参与。上市日期取自沪深北交易所官方列表，每天首次校验时自动更新到数据库的 `stock_info` 表。
- **关注板块：** 按涨停池中的「所属行业」匹配，为空则不限制。
- **股价范围：** 默认 3–100 元。
- **流通市值范围：** 默认 20–5000 亿元。

> **注意：** 自学习、Web【设置】和桌面端【AI设置】会改写 `config/settings.yaml`，文件中的注释会丢失。如果不希望自学习写回文件，设置 `strategy.learning.persist_to_yaml: false`。

## 项目结构

```
├── main.py / server.py     定时任务、Web 服务入口（run_*.py 为其他入口脚本）
├── api/                    FastAPI 接口（/api/v1）、登录、后台任务
├── apps/
│   ├── web/                Web 前端（React + TypeScript + Vite + Tailwind）
│   └── desktop/            Electron 桌面端
├── docker/                 Dockerfile、docker-compose
├── config/                 配置文件
├── scripts/                历史数据回补、数据源检查、打包脚本
├── src/
│   ├── bot/                钉钉、飞书聊天机器人
│   ├── collectors/         数据采集器
│   ├── analyzers/          LLM 客户端与舆情、题材、国际因子分析
│   ├── strategy/           因子评分、综合评分、策略选股与回测、风控
│   ├── services/           流程编排、并发采集、涨停预测、个股诊断、AI 问股、大盘复盘、盘中提醒、组合风险、自学习、AI 研判
│   ├── trading/            订单执行与模拟券商
│   ├── database/           SQLAlchemy 模型与 SQLite 会话
│   ├── desktop/            PyQt6 桌面端（旧版）
│   ├── notifier/           企业微信、钉钉、飞书、邮件推送
│   ├── backtest/           回测引擎
│   └── scheduler.py        定时任务
└── tests/                  测试
```

`backtest/` 目前是独立模块，还没有接入任何入口脚本；信号绩效统计由 `src/services/signal_performance.py` 负责。

## 开发

运行测试（测试不会访问网络；推送到 main 后 GitHub CI 会自动运行后端、前端和桌面端测试）：

```bash
pip install pytest
python -m pytest -q tests/

cd apps/web && npm run lint && npm test && npm run build   # 前端
cd apps/desktop && npm test                                 # 桌面端
```

前端开发：先运行 `python server.py`，再在 `apps/web` 运行 `npm run dev`，打开 http://localhost:5173（接口自动代理到 8000 端口）。

打包：桌面端安装包用 `python scripts/build_desktop.py`；推送 `v*` 标签时 GitHub Actions 会打包 Windows 和 macOS 安装包并上传到 Release。旧版 PyQt6 EXE 仍可用 `powershell .\scripts\build_exe.ps1` 打包（需要自行准备未纳入仓库的 `AStockQuantQt6.spec`）。

提交信息遵循 Conventional Commits（`feat:`、`fix:`、`docs:` 等）。更多约定见 [AGENTS.md](AGENTS.md)。
